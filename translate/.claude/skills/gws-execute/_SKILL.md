# gws-execute

후속 작업을 GWS CLI 명령으로 바꾸고, 승인을 받은 뒤 `gws-executor`로 실행한다.

## 사용 시점

- `notion-db-register`나 `notion-db-analyze`가 후속 작업을 넘겼을 때.
- 사용자가 Gmail, Drive, Docs, Sheets 작업을 직접 요청할 때.

## 참조 문서

- 경로: `.claude/skills/gws-execute/references/`
- 작업 종류별로 문서 하나씩 둔다(예: `gmail.md`, `drive.md`, `docs.md`, `sheets.md`).
- 공통 명령 참조: `docs/gws-commands.md`

## 처리 절차

### 1. 작업 종류 확인

요청된 작업을 하나씩 분류한다:

| 종류 | 예시 |
|------|------|
| Gmail | 초안 작성(기본), 발송(별도 명시 승인 시에만) |
| Drive | 파일 업로드, 폴더 배치(`config/gws.json`) |
| Docs | 문서 생성 및 내용 작성 |
| Sheets | 시트 생성 및 내용 작성 |

### 2. 참조 문서 읽고 명령 구성

1. `references/<종류>.md`가 있으면 명령을 만들기 전에 읽는다.
2. 없으면 `docs/gws-commands.md`를 쓴다.
3. 작업마다 완전한 `gws` 명령을 만든다. 수신자, 제목, 폴더, 내용은 넘겨받은 결과와 템플릿(메일은 `templates/mail/`)으로 채운다.
4. 필요한 값(수신자, 폴더, 파일 이름)이 빠졌으면 **추측하지 않고** 사용자에게 묻는다.

### 3. 미리보기 노출 및 승인 요청

1. `templates/action-plan.md` 양식으로 `workspace/plans/`에 실행 계획을 쓰고, 상태를 `pending`으로 둔다.
2. 사용자에게 한국어로 다음을 보여 준다:
   - 작업 목록
   - **실제로 실행할 명령**(비밀값은 가림)
   - 내용 미리보기(메일 본문, 문서 내용)
   - 메일이면 초안인지 발송인지
3. 사용자의 답을 기다린다.
   - 승인 → 계획 상태를 `approved`로 바꾸고 승인자와 승인 시각을 기록한다.
   - 수정 요청 → 계획을 고쳐 미리보기를 다시 보여 준다.
   - 거절 → 상태를 `rejected`로 바꾸고 중단한다.

### 4. `gws-executor`로 실행

- 승인된 뒤에만 계획 파일 경로를 넘겨 `gws-executor` 서브에이전트를 호출한다.
- 이 스킬에서 `gws` 명령을 직접 실행하지 않는다.

### 5. 결과 보고

- 작업별 결과를 사용자에게 한국어로 보고한다: **결과 링크**(초안, 파일, 문서, 시트), ID, 실패 내역.
- 기록(`workspace/logs/`)과 파일 사본(`workspace/outputs/`)이 저장된 위치도 알린다.

## 제한 사항

- 사용자가 미리보기를 승인하기 전에는 아무것도 실행하지 않는다.
- 메일은 기본적으로 **초안**이다. 발송은 별도 명시 승인이 필요하다.
- 파일을 삭제하거나 공유 설정을 바꾸지 않는다.

## 예외 처리

| 상황 | 조치 |
|------|------|
| 필요한 값 누락 | 계획을 쓰기 전에 사용자에게 물음 |
| 사용자가 계획을 거절 | `rejected`로 표시하고 중단 |
| `gws-executor`가 인증 오류를 보고 | 재인증 방법과 함께 보고 |
| `gws-executor`가 명령 실패를 보고 | 실패한 작업을 보고하고, 자동으로 재시도하지 않음 |
