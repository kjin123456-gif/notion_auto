# notion-db-analyze

키워드 없이 자연어로 들어온 조회·분석 요청을 처리한다.

## 사용 시점

- 입력이 `키워드:내용` 형식이 **아니고**, 사용자가 일정·업무를 조회·필터링·분석하려 할 때.
- 입력에 트리거 키워드가 있으면 `notion-db-register`를 쓴다.

## 처리 절차

### 1. 요청 해석

`docs/intent-map.md`를 보고 다음을 정한다:

| 항목 | 예시 |
|------|------|
| 기간 | 오늘, 이번 주, 날짜 범위 |
| 조건 | 상태(`In progress`, `Done` 등), 담당자, 기타 속성 |
| 대상 DB | intent-map에 있는 DB 하나 이상 |
| 분석 종류 | 마감 확인, 상태별 요약, 담당자별 요약 등 |

- 의도가 불분명하거나 여러 뜻으로 읽히면 **추측하지 않고** 사용자에게 다시 묻는다.

### 2. `notion-agent`로 조회·분석

`notion-agent` 서브에이전트를 다음 값으로 호출한다:

```json
{
  "path": "query",
  "conditions": { "period": "...", "status": "...", "assignee": "..." }
}
```

`notion-agent`는 마감 임박 순으로 정렬해 상태별 건수, 지연 항목, 마감 임박 항목, 담당자별 항목을 돌려준다.

### 3. 보고

- `templates/report.md` 양식으로 사용자에게 한국어로 보고한다.
- 결과가 없으면 그렇다고 알리고, 사용한 조건을 함께 보여 준다.

### 4. 후속 작업 제안

- 결과에 맞는 후속 작업을 제안한다(예: 리마인드 메일 초안, 요약 시트).
- 사용자가 원하면 보고 내용과 함께 **`gws-execute`** 스킬로 넘긴다.
- 이 스킬에서 GWS 작업을 직접 실행하지 않는다.

## 예외 처리

| 상황 | 조치 |
|------|------|
| 의도 불분명 | 가능한 선택지를 보여 주며 재질문 |
| 해당 항목 없음 | 사용한 조건과 함께 "해당 항목 없음"을 보고 |
| DB 접근 불가 | 원인을 보고하고 중단 |
