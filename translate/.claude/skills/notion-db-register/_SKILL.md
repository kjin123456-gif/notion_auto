# notion-db-register

트리거로 분류된 항목을 대상 노션 DB에 등록한다.

## 사용 시점

- 입력에 구분자(`:`)가 있고, 그 앞부분이 트리거 키워드와 일치할 때.
- 키워드가 없는 자연어 요청에는 쓰지 **않는다**. 그때는 `notion-db-analyze`를 쓴다.

## 처리 절차

### 1. 대상 DB 결정

- 트리거 키워드로 대상 DB를 정한다.

### 2. 내용을 속성별로 나누기

구분자 뒤의 내용을 대상 DB 속성에 나눈다. 속성 이름과 유형은 `config/notion.json`에 정의되어 있다.

| DB | 속성 | 추출 방법 | 예시 |
|----|------|-----------|------|
| Personal Tasks | `일정이름` (제목) | 날짜·시간·사람·장소를 뺀 핵심 문구 | `친구와 카페약속` |
| | `날짜` (날짜) | 상대·절대 표현 → 오늘 날짜 기준 ISO 8601 | `토요일 3시` → `2026-11-21T15:00` |
| | `사람` (사람) | 입력에 나온 노션 사용자 | `me` |
| | `중요도` (선택) | 언급되면 `높음` / `중간` / `낮음` | `높음` |
| | `위치` (텍스트) | 입력에 나온 장소 이름 | `강남역` |
| Work | `업무이름` (제목) | 날짜·사람·메일 주소를 뺀 핵심 문구 | `주간 보고서 제출` |
| | `등록날짜` (날짜) | 항상 오늘(자동 입력) | `2026-11-15` |
| | `마감일` (날짜) | 입력의 마감·예정 날짜 → ISO 8601 | `금요일 5시` → `2026-11-20T17:00` |
| | `공동작업자` (사람) | 입력에 나온 노션 사용자 | — |
| | `전송메일` (이메일) | 입력에 나온 메일 주소 | `someone@example.com` |
| | `중요도` (선택) | 언급되면 `높음` / `중간` / `낮음` | — |
| Study | `학습 주제` (제목) | 날짜를 뺀 핵심 문구 | `파이썬 강의 3강` |
| | `마감일` (날짜) | 마감·예정 날짜 → ISO 8601 | `목요일` → `2026-11-19` |
| | `요약` (텍스트) | 입력의 추가 내용 | — |

- 입력에 없는 속성은 비워 둔다. DB에 상태 속성이 없으므로 상태는 넣지 않는다.
- 날짜·시간이 모호하면(예: 요일 없는 "다음 주") **추측하지 않고** 사용자에게 다시 묻는다.

### 3. `notion-agent`로 등록

`notion-agent` 서브에이전트를 다음 값으로 호출한다:

```json
{
  "path": "register",
  "keyword": "<트리거 키워드>",
  "target_db": "<대상 DB>",
  "content": { "<속성 이름>": "<값>", "...": "..." }
}
```

### 4. 결과 보고

- `templates/register-result.md` 양식으로 사용자에게 한국어로 보고한다.

### 5. 후속 작업 넘기기

- 입력이나 사용자 요청에 후속 작업(리마인드 메일, Docs/Sheets 파일 등)이 있으면 등록 결과와 함께 **`gws-execute`** 스킬로 넘긴다.
- 이 스킬에서 GWS 작업을 직접 실행하지 않는다.

## 예외 처리

| 상황 | 조치 |
|------|------|
| 키워드가 어떤 트리거와도 맞지 않음 | 등록하지 않고, 쓸 수 있는 키워드를 보여 주며 재질문 |
| 날짜·시간 해석 불가 | 등록하지 않고, 사용자에게 날짜·시간을 물음 |
| `notion-agent`가 속성 불일치를 보고 | 맞지 않는 속성을 보고하고 진행 방법을 물음 |
| DB 접근 불가 | 원인을 보고하고 중단 |
