────────────────────────────────
1. trigger-register (트리거 일정 등록)
────────────────────────────────
- 목적: "키워드:내용" 입력을 해석해 해당 노션 DB에 일정 등록
- 사용 시점: 입력에 구분자가 있고 앞부분이 트리거 키워드와 일치할 때
- 절차
  1) 트리거 캐시 확인 (없거나 오래되면 /sync-triggers)
  2) 키워드 대조 → 대상 DB 결정
  3) 내용 파싱 (제목, 날짜·시간) - docs/trigger-rules.md 기준
  4) 기본값 적용 후 notion-agent로 등록
  5) templates/register-result.md 양식으로 보고
- 예외: 키워드 미일치, 날짜 해석 불가 → 재질문

────────────────────────────────
2. schedule-check (일정·마감 조회)
────────────────────────────────
- 목적: 오늘·이번 주 마감 또는 일정 조회 후 보고
- 사용 시점: "오늘 마감작업 확인해줘" 등 조회 요청
- 절차
  1) 조회 기간·대상 DB 결정 (docs/intent-map.md)
  2) notion-agent로 조회·정렬 (마감 임박 순)
  3) templates/report.md 양식으로 보고
  4) 후속 작업 제안 → 원하면 실행 계획 작성
- 출력: 보고서, (선택) 실행 계획 파일

────────────────────────────────
3. mail-draft (메일 초안 작성)
────────────────────────────────
- 목적: 보고 결과를 바탕으로 Gmail 초안 작성
- 사용 시점: 사용자가 메일 작성을 요청하거나 승인했을 때
- 절차
  1) 수신자·제목·본문 결정 (templates/mail/ 사용)
  2) 실행 계획에 미리보기 포함 → 승인 요청
  3) 승인 후 gws-executor로 초안 생성
  4) 발송은 별도 명시 승인 시에만
- 주의: 수신자 확인 필수, 기본값은 "초안"

────────────────────────────────
4. file-create (구글 파일 제작)
────────────────────────────────
- 목적: Docs/Sheets 문서 생성 및 Drive 저장
- 사용 시점: 보고서·목록을 파일로 만들어 달라는 요청
- 절차
  1) 파일 종류·이름·저장 폴더 결정 (config/gws.json)
  2) 내용 구성 → 실행 계획 작성 → 승인 요청
  3) 승인 후 gws-executor로 생성
  4) 링크 보고, 사본은 workspace/outputs/에 저장
- 주의: 공유 설정은 변경하지 않음
